# 보관함 표시 설정

**태그 정리**에서 전체 출처 / DLsite / RPLAY를 골라 숨길 원본 태그를 선택한다. 선택한 출처의 카드·상세·태그 필터·태그를 통한 검색에서 제외하며, 체크를 해제하고 저장하면 복원된다. 다른 출처와 개인 태그는 유지한다. 전체 출처에서 같은 표시명의 태그를 체크하면 두 출처의 해당 원문들을 함께 숨긴다. 일부 출처에서만 숨겼으면 부분 선택 표시가 나타난다. 같은 단어가 제목이나 파일명에 있으면 해당 제목·파일명 검색에는 계속 일치한다. 숨김은 `data/tag-visibility.json`에 revision 및 출처별 원문 목록과 함께 서버에 저장하며 다른 기기에서도 다시 불러올 때 적용된다. 원본 DB·출처 snapshot·`/api/export`는 바꾸지 않는다. 다른 기기에서 먼저 저장했으면 오래된 화면의 저장을 거절한다. 손상된 파일은 덮어쓰지 않으며 배포·백업 시 이 파일도 보존한다. 이전 RPLAY 전용 저장 파일은 읽을 때 DLsite 숨김 0개로 해석하고 기존 RPLAY 설정은 유지한다. 이전 클라이언트의 RPLAY 전용 저장도 DLsite 설정을 지우지 않는다.

태그는 원문을 그대로 보존하면서 화면에서 중복을 묶는다. 기존 공식 한국어 표시 사전에서 동일한 이름으로 확인된 일본어·한국어 태그와 영문 대소문자 차이를 같은 필터 키로 사용한다. 예: `癒し`와 `힐링`, `ASMR`와 `asmr`. 확인되지 않은 동의어는 합치지 않는다. 카드·상세·필터의 표시 이름은 한 번만 나오고, 마우스를 올리면 해당 원문들을 확인할 수 있다. 한국어·원문 어느 쪽으로 태그 검색해도 같은 묶음에 도달한다.

상단 **표시 설정**에서 태그는 한국어 또는 일본어 원문 한 가지를 고른다. 공식 한국어 이름이 확인되지 않은 태그와 내 태그는 저장된 이름을 유지한다. 검색은 표시 언어와 관계없이 한국어·원문 모두 지원하며, 선택 키와 개인 설정에는 원문 태그를 사용한다.

제목은 한국어 우선 / 일본어 원문 우선 / 한국어 + 원문 중 선택한다. DLsite 공식 상품 API와 상품이 명시한 언어판 링크에서 제목을 읽고 `data/covers/dlsite-RJ….json`의 `titles.ja`, `titles.ko`, `title_sources`에 따로 저장한다. 한국어 제목은 ko_KR 응답에서 확인된 경우에만 제공하며, 없으면 원문·기존 등록 제목으로 돌아간다. 같은 제목은 한 번만 표시한다. RPLAY 제목은 기존 값을 유지한다. 관련 언어판을 찾는 것은 제목 표시용이며 작품·판본을 합치거나 DB 제목·ID·원본 스냅샷을 바꾸지 않는다. 공개 원문 상품이 사라졌으면 해당 언어 제목은 미확인 상태로 남는다.

태그 버튼은 누를 때마다 **선택 안 함 → 포함 → 제외 → 선택 안 함**으로 바뀌며 키보드 Enter/Space도 동일하다. 포함 태그는 모두 있어야 하고, 제외 태그는 하나라도 있으면 해당 작품을 숨긴다. 필터 제외는 일시적인 검색 조건이며 서버에 저장하는 원본 태그 숨김 설정과 다르다. 태그 옆 숫자는 현재 출처·검색·감상 버전·즐겨찾기·포함/제외 조건에 해당하는 **작품 수**다. 한 작품의 여러 판본·원문/번역 중복은 한 번만 센다. 페이지 크기는 개수에 영향을 주지 않는다. 0개인 태그도 상태 변경을 위해 유지한다. 선택 해제는 포함·제외를 함께 비운다.

정렬은 등록일 최신/오래된순, 제목 오름/내림차순, 출처, RJ 코드, 전체 판본의 트랙 수 많은/적은순, 기본 감상 버전의 총 재생 시간 긴/짧은순이다. 재생 시간은 선택한 감상 필터에 해당하는 기본 버전을 기준으로 하며 길이가 하나라도 미확인이면 마지막에 표시한다. 실제 최근 재생 시각은 저장하지 않으므로 최근 재생순은 만들지 않는다. 페이지당 12/24/48/96개 또는 전체를 선택할 수 있다. 언어·정렬·표시 개수는 이 브라우저의 `audio-display-settings-v1`에 저장되며 로그인 계정 간 동기화는 아직 없다.

**누락된 표지 가져오기**는 인증된 `/api/editions/{id}/cover/refresh`를 두 요청씩 호출한다. 양호한 로컬/앱 캐시는 그대로 재사용하고 실패 캐시만 다시 시도한다. DLsite 번역판 URL의 부모 RJ를 임의로 따라가지 않고 저장된 출처 ID의 고정 API를 요청한다. 공식 API의 대표 이미지가 명시된 원작/언어판 RJ를 가리킬 때만 그 이미지 주소를 허용한다. 오래된 사이드카 표지 주소가 실패하면 공식 정보로 대체한다. 원본 미디어·DB에는 쓰지 않는다. 공개 이미지가 없거나 404이면 자리표시자를 유지하고 로그인·리다이렉트·차단을 우회하지 않는다.

로컬 검증과 NAS 반영은 별도다. 작업자가 준비한 소스와 공개 메타데이터/누락 표지 캐시는 메인에서 기존 Host 허용·서비스 구성·DB·재생 진도·캐시를 보존하여 검토하고 반영한다.

## 보유본·음성 언어·트랙 제목

`같은 작품 묶기`는 동일한 출처 ID 또는 공식 상품 API가 명시한 일본어판 제목 출처 ID로 확인되는 항목만 화면에서 묶는다. 제목이 같다는 이유로 묶지 않는다. 카드의 보유본 목록에서 각각 열 수 있고 즐겨찾기도 보유본별로 유지한다. 이 설정을 끄면 모든 보유본을 각각 표시한다. 원본 파일, DB, 판본/트랙/재생 ID와 진도를 합치거나 지우지 않는다. 태그 수는 묶은 상태에서는 조건에 해당하는 묶음 수를 기준으로 하며 각 보유본의 태그를 합쳐 표시한다.

RJ 표시는 work_codes 외에도 저장된 DLsite 출처/provenance에서 확인한다. 별도 보유본의 code 제약으로 work_codes가 비어 있어도 실제 출처 RJ는 표시한다. RPLAY는 별도 namespace이므로 RJ가 필요하지 않다. 출처 RJ가 파일 내용의 동일성을 검증하는 것은 아니다.

`음성 언어 미확인`, `한국어 음성`, `일본어 음성`과 자막 언어를 따로 표시하고, 음성 언어 및 태그 미등록 필터를 제공한다. 한국어 제목·태그·자막이나 파일명으로 한국어 더빙을 추정하지 않는다. import의 `audio_language_unverified`가 참이면 미확인으로 남긴다. 태그가 없으면 `태그 미등록`을 표시하며 임의 태그를 만들지 않는다.

트랙 제목은 한국어+원문 / 한국어 우선 / 원문을 선택하며 기본은 함께 표시다. 목록·폴더 보기·플레이어 제목·재생 대기열에 적용된다. `data/title-translations.json`의 원문 해시를 검증한 별도 표시 캐시를 읽어 한국어를 붙이고 자동번역 여부를 표시한다. 공식 작품 한국어 제목은 이 캐시보다 우선한다. 캐시가 없거나 잘못됐으면 원문으로 동작하며, DB 제목과 파일 경로는 그대로다. API나 NAS에서 번역 모델을 실행하거나 외부 번역 서비스로 자료를 보내지 않는다. 실제 번역 캐시 생성 방식은 사용자의 자동번역 선택에 따른다.

## 자동번역 검사와 직접 수정

사용자는 로컬 자동번역과 원문 보존을 선택했다. 모델의 거절 문구, 미번역, 번호 누락, 잘린 응답, 과도한 축약과 일부 핵심 용어의 누락을 검사한다. 검열·의미 완화 표시는 의심 단계이며 원인을 확정하지 않는다. 자동번역은 모두 미검수 상태이고, 사용할 수 없는 결과는 번역문 대신 원문을 표시한다. 원문·번역 후보·모델·검사 사유를 보관한다. 줄 대응에 실패했으면 묶음 응답도 구분해 보존한다. 문제 항목은 `번역 검토 필요` 필터로 찾는다. 거절 결과를 다른 지시로 우회해 번역하지 않는다.

작품 상세의 `한국어 제목 편집`, 각 트랙의 `한국어 트랙명 편집`에서 번역을 수정하거나 비어 있는 번역을 직접 입력한다. `검수 완료`, `검열·의미 완화 의심`도 사용자가 표시할 수 있다. 원문은 편집 대상이 아니며 한국어만 이 서버에 저장한다. 저장 우선순위는 직접 입력 > 공식 한국어 > 자동번역 > 원문이다. 같은 원문 이름을 가진 다른 작품/트랙에는 수동 수정이 전파되지 않는다.

자동번역은 앱 데이터 `title-translations.json`, 직접 입력은 `title-overrides.json`에 분리한다. 수동 저장은 임시 파일의 원자 교체와 서버 내 잠금으로 보호하고, revision이 바뀌면 오래된 화면의 저장을 거절한다. 이전 수동 값은 최근 10개까지 저장 기록에 보존한다. 자동번역을 다시 생성하거나 서버를 재시작해도 직접 입력을 덮어쓰지 않는다. 손상된 수동 저장 파일을 읽지 못하면 경고하고 새 저장을 중지한다. 배포·백업 때 두 파일을 보존해야 하며, 새 자동번역 seed로 수동 파일을 덮으면 안 된다. 기존 `/api/export`는 원래 카탈로그를 그대로 내보내므로 두 번역 파일은 별도 앱 데이터 백업에 포함한다.

편집 API는 기존 인증과 같은 출처 검사를 거쳐 `/api/works/{id}/title-translation`, `/api/tracks/{id}/title-translation`에 저장한다. DB 제목·원본 JSON·미디어 경로·재생 ID/진도는 바꾸지 않는다. 재생 중 제목 정보가 갱신돼도 미디어를 다시 로드하지 않는다. 현재는 단일 관리자 서비스의 서버 저장이며 로그인 계정별 분리는 이후 로그인 작업 범위다.
## 통합 태그 관리와 정렬

태그는 DLsite/RPLAY 구분 없이 한 목록에서 관리한다. 기본으로 열린 태그 필터에서 선택한 포함·제외 태그, 좋아요한 태그, 나머지 순서로 표시한다. 각 구간 안에서는 현재 조건의 작품 수 많은순·적은순, 이름순, 랜덤을 선택한다. 같은 작품 묶기 상태에서는 묶음당 한 번 센다. 작품 정렬에도 랜덤과 다시 섞기를 제공하며 페이지 이동·조건 변경만으로 다시 섞지 않는다. 정렬 선택은 이 브라우저에 보존한다.

태그 관리에서 표시 이름과 원문 표시 이름을 수정하거나 비워 기본값으로 돌릴 수 있다. 체크한 태그의 대표 태그를 골라 명시적으로 병합하며, 이름만 같게 편집했다고 자동으로 병합하지 않는다. 병합은 기존·추후 태그의 표시와 검색·필터를 같은 키로 묶으며 원본 태그와 카탈로그 행은 수정하지 않는다. 병합 해제로 원래 그룹을 분리할 수 있다. 기존 이름과 수정한 이름 모두 검색 가능하다.

이름·병합·태그 좋아요·전체 숨김은 앱 데이터 `tag-visibility.json`에 서버 공통으로 저장하며 다른 기기에서도 유지한다. 기존 출처별 숨김 설정도 읽고 보존한다. 새 숨김·복원은 통합 그룹에 적용하며 원본과 입력한 개인 태그는 삭제하지 않는다. revision 충돌은 저장을 거절하고 초안을 남긴다. 카탈로그 내보내기는 원본이므로 이 설정 파일은 앱 데이터 백업에 따로 포함한다. 관리 화면 변경은 아래 변경 저장을 눌러야 적용한다. 필터의 좋아요 버튼은 즉시 서버에 저장한다.
## 자막·대본·더빙 분류

판본별로 자막파일, 영상 자체 자막(선택형 스트림/붙박이/둘 다), 대본, 더빙, 실제 음성 언어를 분리한다. 파일명·한국어 제목·자막 언어로 더빙이나 음성 언어를 확정하지 않는다. 연결된 자막은 실제 등록·파싱된 파일이라는 근거만 사용하며 번역 품질·음성 싱크 검증과 구분한다. 미연결은 없음이 아닌 미확인이다. 기존 profile.translation 자막판 표기도 실제 영상 검사로 간주하지 않는다.

자막 있음은 연결된 자막파일 또는 직접 확인 기록이 있는 경우다. 없음은 직접 파일 없음 확인 및 영상인 경우 영상 자체 자막 없음까지 확인해야 한다. 대본·더빙은 직접 확인한 없음/있음과 미확인을 구분한다. TXT/PDF/읽어주세요 등의 이름만으로 대본을 추정하거나, 한국어 음성이라는 이유로 더빙이라고 단정하지 않는다.

독립 필터는 같은 판본이 자막·대본·더빙 및 음성 언어 조건을 모두 만족할 때만 작품을 보여준다. 자막 탐색 메뉴도 확인된 자막만 포함한다. 다른 판본의 자막과 더빙 정보를 섞어 일치시키지 않는다.

상세의 자막·대본·더빙 확인/수정에서 항목과 메모를 저장한다. 원본 DB/미디어는 수정하지 않고 별도 앱 데이터 media-details.json에 판본ID와 revision으로 저장한다. 다른 기기에서도 유지하며 충돌 시 초안 보존·저장 거절이다. 연결된 자막을 없음으로 덮는 모순은 차단한다. 파일을 읽기만 해서는 생성하지 않으며 오류난 파일은 보존하고 쓰기를 중지한다. 배포 백업에는 이 파일도 포함한다. /api/export는 원본 카탈로그 그대로다.

이번 구현은 영상 OCR/자막 스트림 전수검사/대본 일괄 스캔/음성 언어·더빙 ASR을 실행하지 않는다. 현재 확인 근거가 없는 항목은 미확인으로 유지하며 원본 미디어를 바꾸지 않는다. 영상 내 선택형 자막은 분류 기록이며 모든 브라우저에서 재생 선택을 지원한다는 뜻은 아니다.
