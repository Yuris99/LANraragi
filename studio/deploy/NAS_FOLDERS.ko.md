# NAS 이미지 폴더 연결 검토안

## 현재 상태와 적용 경계

사용자 보고로 NAS의 두 서비스 healthy, Windows SSH 터널, Studio 관리자 로그인을 확인했다. 사용자가 원본의 전체 절대 경로를 확인했고, NAS에서 읽기 전용 계획 검사를 실행했다. `manga`와 `images`에서 오류 각 1개, 등록 0개가 보고됐다. 두 하위 경로는 존재하며 기본 권한은 0777, 소유자는 확인한 운영 계정이고 Synology ACL(`+`)이 있다. **컨테이너의 실제 오류 번호와 읽기 가능 여부는 미확인**이다. 이 결과만으로 ACL 문제라고 단정하거나 권한을 변경하지 않는다. 개인 원본·파일 목록·DB를 클라우드/GitHub에 복사해 검증하지 않는다.

이번 구성은 압축을 풀어 둔 JPG/JPEG/PNG/WebP/GIF/AVIF/JXL 폴더를 위한 선택적 작업자다. 기본 하위 컬렉션 이름은 `manga`, `images`이며, 사용자 선택에 따라 JSON 목록에 추가할 수 있다. 실제 디코딩/리더 지원은 설치된 LANraragi 이미지에 달려 있다. PNG/JPEG/WebP의 실제 서비스 검증 결과는 CLOUD_VALIDATION.md에 별도로 기록한다.

## 원본과 저장소

- 확인된 원본 루트 하나만 `/nas-library`로 **읽기 전용** 연결한다. `create_host_path: false`로 오타 디렉터리를 만들지 않는다. 기존 소유권/ACL을 바꾸거나 재귀 chown하지 않는다. 읽기/탐색 권한이 없으면 중단하고 해당 경로의 최소 권한을 따로 검토한다.
- 선택한 컬렉션 아래 **이미지가 직접 들어 있는 각 폴더를 한 권/한 묶음**으로 등록한다. 하위 폴더도 별개로 검사하며 부모의 직접 이미지와 한데 합치지 않는다. 숫자는 자연 정렬(`1`, `2`, `10`)하고 파일 이름을 순번으로 바꾼 CBZ를 생성한다. 기존 이미지 이름/내용은 바꾸지 않는다.
- 생성 파일은 기존 전용 `studio-uploads` 볼륨에만 저장한다. 원본 이동/삭제/재압축을 하지 않는다. 읽기용 사본만큼 추가 공간이 필요하고, 생성 중에는 약 두 배의 파일 크기 + 64 MiB 여유를 확인한다. 삭제나 원본 변경으로 사본을 자동 삭제하지 않는다. 원본이 달라지면 이전 사본을 보존하고 새 판본을 생성한다.
- 출처 폴더와 원래 파일 순서를 CBZ의 `studio-folder.json` 및 NAS SQLite 영수증에 보존한다. 호스트 절대 경로는 CBZ에 넣지 않는다. 색인 후 `folder:manga/…` 같은 사용자 태그로 구분한다. 긴 경로는 컬렉션 태그로 줄인다. 현재 화면은 폴더 트리가 아니라 태그 필터이며, 기존 출처 태그/댓글을 변경하지 않는다.
- 숨김 경로, 심볼릭 링크, Synology `@eaDir`, `@tmp`, `#recycle`은 건너뛴다. 디렉터리 descriptor와 `O_NOFOLLOW`로 경로를 고정하고 읽기 전후 파일/폴더 상태를 비교한다. 변경 중이면 게시하지 않는다. 기본 안정화 대기 30초.
- 기본 한도는 한 번에 신규 한 권, 한 검사에서 1,000개 디렉터리, 폴더당 이미지 2,000개, 항목 10,000개, 이미지당 64 MiB, 생성 CBZ 512 MiB다. 이미지 자체는 압축하지 않아 DS718+ CPU 비용을 낮춘다. 조회/생성 동시 실행 수는 1로 운용한다.
- 중단된 생성물은 게시되지 않는다. 게시 후 DB 영수증 저장 전에 중단되면 같은 CBZ 해시로 재개한다. 완료 영수증과 남은 검사 큐는 SQLite에 저장되어 재실행 시 중복을 피하고 뒤쪽 폴더를 계속 검사한다. 영수증이 있으면 사용자가 삭제한 사용자 태그도 되살리지 않는다.

## 준비할 변경

`compose.folders.yaml`의 `folder-import`는 profile로 분리된 **수동 일회성 서비스**다. 기본 명령은 `plan`으로 메타데이터 수/오류만 출력하고 DB/원본/업로드에 쓰지 않는다. 네트워크는 `none`, 비루트 UID/GID, 읽기 전용 컨테이너 루트, 메모리 256 MiB이며 포트를 열지 않는다. 기존 LANraragi/Studio/NMLO/Stash를 재시작할 필요가 없다.

현재 NAS에 로드된 이전 Studio 이미지에는 이 새 모듈이 없다. 고정 커밋의 `folder_importer.py`를 NAS의 새 전용 설정 경로에 두고 **작업자에만 읽기 전용 연결**하는 방식으로 기존 이미지를 재사용할 수 있다. `STUDIO_FOLDER_IMAGE`는 작업자 전용 불변 ID이며 기존 `STUDIO_WEB_IMAGE` 선택을 덮어쓰지 않는다. 새 Compose 파일/모듈 해시/사용자 확인 원본 경로는 NAS 안의 별도 설정 파일에 보관한다. 비밀 값을 재생성하거나 내보내지 않는다. 이 모듈의 기존 NAS 이미지 호환 검증 결과는 CLOUD_VALIDATION.md에 기록한다.

새로 다운로드한 **코드 파일 하나만** `0644`로 준비해 작업자 UID가 읽을 수 있게 한다. 이는 비밀 없는 소스 코드이며 원본 미디어 폴더의 권한 변경을 뜻하지 않는다. 새 설정 경로와 실제 원본 루트가 서비스 UID에 의해 접근 가능한지도 계획 단계에서 검증한다. 제한적인 umask로 만든 합성 테스트 디렉터리/코드 파일은 처음에 읽기가 거부됐고, 해당 신규 테스트 대상만 수정한 뒤 재검증했다. NAS 기존 경로의 권한은 자동으로 바꾸지 않는다.

1. 전체 원본 경로와 일반 계정 UID/GID가 읽기/탐색 가능한지 NAS에서 읽기 전용으로 확인한다. 파일 목록은 채팅으로 보내지 않는다.
2. 기존 프로젝트의 전용 DB/업로드 볼륨, 사용할 이미지 ID, 추가 설정 파일, 원본 RO mount를 구체적으로 제시하고 검토한다.
3. 승인된 구성에서 `plan`으로 권한/준비/오류 수를 확인한다. 전체 폴더를 바로 가져오지 않는다.
4. 첫 시험은 `manga` 또는 `images`의 사용자가 선택한 작은 하위 폴더 한 개만 지정해 `--operation import --limit 1`로 실행한다. 파일명/미디어는 NAS 안에서만 처리된다.
5. 브라우저 동기화 → 썸네일 → 원본/모자이크 리더 → 이어 읽기 → `folder:` 태그 → PC 다운로드 → 동일 입력 재실행 중복 없음 → 원본 보존을 확인한다. 기존 서비스의 읽기 진행률/태그와 원본 권한도 그대로인지 확인한다.
6. 결과를 확인한 뒤에만 선택 컬렉션 범위를 넓힌다. 백그라운드 전체 감시/무제한 일괄 등록은 아직 켜지 않는다. 수동 실행의 저장된 검사 큐가 한 바퀴 끝나면 다음 실행에서 변경 검사를 다시 시작한다.

되돌리기는 일회성 작업자 실행을 중단하고 추가 설정/서비스를 사용하지 않는 것이다. 기존 서비스, 원본 및 생성된 파일/영수증은 그대로 보존한다. 임의 `down -v`, 볼륨 삭제, 기존 원본 이동/삭제는 사용하지 않는다.

## 계획 검사에 오류가 있을 때

`--operation diagnose`는 같은 비루트/읽기 전용/네트워크 없는 컨테이너에서 실행한다. UID/GID/보조 그룹/UID 매핑, 원본 루트와 설정된 컬렉션의 mode/소유 ID/열기 여부/읽기 전용 mount, 직접 이미지·하위 폴더 수, errno 또는 검사 한도 오류만 출력한다. 개인 책/파일명과 이미지 내용, 호스트 절대 경로, ACL 전체, DB·비밀 값은 출력하지 않으며 가져오기/권한 변경을 하지 않는다. `manga`/`images`의 대소문자 차이는 선택한 이름과 대응하는 최상위 이름만 확인한다.

일반 `plan`/`import`에도 최대 20개의 컬렉션별 오류 종류를 추가했다. `errno=13`은 접근 거부, `2`는 해당 경로 없음, `20`/`40`은 디렉터리/심볼릭 링크 경로 문제의 근거가 될 수 있다. `opened=true` 뒤의 검증 오류는 이미지 수/크기 등 검사 한도도 확인해야 한다. 로그에 개인 파일명이 섞일 수 있는 전체 OSError 문자열은 내보내지 않는다.

사용자 NAS 진단에서는 UID1026/GID100, 보조 그룹 `[100]`, 원본 루트 소유 UID1026/GID100, 컨테이너 안 mode 000, errno13을 확인했다. 호스트의 mode0777+와 다르므로 **컨테이너에 기존 NAS 계정의 보조 그룹이 빠진 경우**를 다음으로 구분한다. 아직 원인이 확정되거나 NAS 접근이 복구된 상태는 아니다.

`probe-folder-groups.sh`는 일반 NAS 계정에서 실행하며 `id -G`로 관찰한 기존 그룹만 일회성 컨테이너에 `--group-add`로 전달한다. 특정 관리자 그룹 번호를 추측하거나 NAS 계정의 그룹/ACL을 추가하지 않는다. 기본 `preview`는 아무것도 생성하지 않고, `diagnose`/`plan`만 허용한다. root로 전체 스크립트를 실행하면 거부한다. sudo는 확인된 비루트 ID/그룹을 캡처한 뒤 명시적 로컬 Docker 호출에만 사용한다. 네트워크 없음, 읽기 전용 원본/코드, 이미지 pull 금지, DB/업로드 쓰기 mount 없음, 기존 서비스 재시작 없음은 유지한다. 다운로드한 진단 모듈은 고정 커밋/SHA256으로 확인한다. 성공하면 향후 폴더 작업자에만 검증된 보조 그룹 구성을 준비하고, 계속 실패하면 해당 원본 루트의 ACL을 읽기 전용으로 확인한다. 광범위한 chmod/chown, ACL 우회, root/privileged 작업자로 바꾸지 않는다.
