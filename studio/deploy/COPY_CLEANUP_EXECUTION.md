# Actual app-copy cleanup

`apply-nas-copy-cleanup.sh apply <approved NAS root>` is one NAS-local action. It uses the already saved private copy review, synchronizes the current catalog, automatically revalidates candidates, verifies full downloads through the existing internal LANraragi API, backs up both catalog and complete copy bytes, merges records, and unlinks the exact verified app-copy file. No separate plan command or private-report upload is required. Unknown, changed or ambiguous copies remain. Original archives are mounted RO throughout; original directories, ACLs, Stash and NMLO are not changed.

The app-only release supplies alias-aware Studio code first. The local wrapper checks its exact runtime manifest, original app image, configured nonroot Studio identity, known own volumes and existing RO original-path LRR mount. Existing local controller hashes must agree. The wrapper cannot install or modify that controller. It acquires the existing deployment locks and the executor uses the same import lock as the fixed folder worker. There are no Docker socket mounts in helper containers.

Verification downloads happen inside the existing Studio container using its current LRR credentials, never exposing those values. Only fixed40hex archive IDs are accepted; full SHA256 and byte length must match. The executor itself has network disabled. Provider IDs, filenames, partial LRR hashes or matching titles never suffice to authorize an unlink. LANraragi0.9.81 can return extensionless filenames; those are accepted only alongside full file/backend proofs.

Studio enters a brief maintenance stop during mutation to avoid user edits racing a merge. Active downloads or folder jobs block maintenance. Only Studio is restarted afterward; LRR is not restarted or reconfigured. A root-owned maintenance marker permits recovery of a dead owner only when both own lock PIDs agree and no copy executor remains. Live or unknown work is preserved.

## Records and recovery

Sources retain their IDs, original URLs, source tags and comments when moved to the surviving work. User tags and library tags are preserved, favorites combine, rating/progress use their maximum valid value, and both scalar records are archived in the journal. Conflicting explicitly locked metadata, excessive user-tag unions or invalid progress hold that copy. Former UUIDs and local-number bookmarks resolve to the survivor; qualified source numbers follow transferred sources. The old work row and local number are retained as an alias, not displayed as another work. Retired LRR IDs are tombstoned so delayed backend indexing cannot recreate a removed copy. Retired upload entries disappear from active file management.

The original catalog is never opened as root during preparation: DB+WAL snapshots are read with file descriptors and SQLite only reads the private clone. During mutation every SQLite operation runs as the configured app UID/GID, including WAL/SHM handling; no operator supplementary groups are inherited. A consistent full database backup is made before each new merge. Brief privilege elevation only publishes the backup into the private report output, not for source-database operations.

Private full-copy archives and database backups remain under the app's dedicated `review-reports/cleanup-execution` directory outside library mounts. They preserve copy-only non-page files and provide rollback; active duplicates disappear but backup bytes still occupy NAS storage. Backups are never auto-expired. To roll back, stop only Studio, restore the appropriate pre-cleanup database plus the archived copies to their exact prior upload names/ownership, then start Studio and allow LRR indexing. Restoring archive bytes alone does not clear retirement tombstones. Review the local manifest/journal before restoration.

A durable SQLite retirement entry is committed before unlink. Interruption after merge leaves the verified copy and redirects in place; rerun resumes. Interruption after unlink is finalized from the journal and verified backup without a second deletion. Fresh survivor/hash checks and fresh internal backend proof remain necessary on retry. Disk space is checked before mutation. Never remove a live/unknown executor or lock to force progress.

## Validation boundaries

Unit tests use disposable generated archives and databases and execute real unlink, verify unchanged original bytes and byte-identical backups, preserve comments/favorites/tags/old IDs, prevent stale-index resurrection, resume both interruption points and reject missing proof, changed files or conflicting edits. The independent real Docker/LRR/Studio/Chromium rehearsal verifies full backend downloads, actual copy removal, source bytes, old-bookmark reader page and file download, with LRR identity/start time unchanged. NAS execution remains operator-local and must be reported separately from synthetic validation. This does not rename original folders or complete live-site source matching.
