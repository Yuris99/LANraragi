# NAS 전용 서비스 계정과 현재 중단 지점

> **후속 승인:** 사용자가 root 원본 읽기 방식의 시험을 승인했다. 현재 한 폴더 시험은 [ROOT_FOLDER_PILOT.ko.md](ROOT_FOLDER_PILOT.ko.md)를 따른다. 새 NAS 계정 생성은 이 시험의 선행 조건이 아니다. 아래 개인 계정 그룹 상속 절차는 계속 폐기 상태이며 기존 상시 서비스 신원 이전은 별도 범위다.

2026-10-17 사용자 지시: 개인 NAS 계정의 권한을 앱에 재사용하지 않는다. 앞선 개인 계정 기반 검사/등록 절차는 폐기한다. 이 문서는 기존 설치를 자동 변경하는 실행 스크립트가 아니다.

## 무엇을 위한 작업인가

Studio는 NAS의 개인 만화를 브라우저에서 목록/썸네일/태그/리더/이어 읽기/다운로드로 이용하는 앱이다. 클라우드는 코드 개발과 합성 자료 검증용이다. 실제 앱과 개인 자료는 NAS에 둔다. 기존 NMLO와 Stash는 변경하지 않는다.

현재 NAS는 별도 pilot 프로젝트의 서비스 실행과 SSH 터널/관리자 웹 로그인이 사용자에 의해 확인됐다. 개인 이미지 폴더는 읽기 전용 계획 검사만 성공했다(326개 후보,16,896개 이미지 확장자 경로). 실제 개인 작품 등록/리더/다운로드는 확인되지 않았다. 계획 검사는 이미지 내용 열람이나 클라우드 업로드가 아니다.

현 폴더 연결 구현은 원본을 직접 읽는 리더가 아니라, 원본을 읽어 전용 uploads 볼륨에 CBZ 사본을 만드는 방식이다. 원본 보존 대신 사본 저장 공간과 초기 작업 시간이 필요하다. 원본 폴더를 직접 읽는 리더는 구현 완료로 표시하지 않는다. 전체 자동 등록은 시작하지 않는다.

## 기존 신원 사용과 조치

- 기존 설치 구성은 Studio의 `STUDIO_UID=1026`, `STUDIO_GID=100` 및 LANraragi 앱의 동일 UID/GID를 사용한다. 이는 개인 계정 Yuris의 파일 접근 신원이다. 비밀번호를 넣지 않았다는 사실이 계정 권한 분리를 뜻하지 않는다. LANraragi 이미지 초기화 프로세스와 앱 실행 신원은 구분한다.
- 임시 검사 컨테이너에는 사용자의 실제 그룹100/101도 전달했으며, 그룹101은 Synology administrators이다. 원본 RO/no-network였어도 사용자 권한 재사용은 사실이다.
- 최신 브랜치의 `probe-folder-groups.sh`와 `import-one-folder.sh`는 모든 실행을 거부한다. 선택 폴더 Compose에서 보조 그룹 상속을 제거했다.
- 기존 고정 커밋 URL, 사용자가 이미 다운로드한 스크립트/이미지/설정은 자동 폐기되지 않는다. 이전 명령을 다시 실행하지 않는다.
- 이 코드 수정은 NAS의 실행 중 컨테이너, UID, ACL, 계정, 소유권을 바꾸지 않는다. 실제 NAS 전환은 아직 수행하지 않았다.

## 전용 계정의 권한 범위

이 NAS에 이름 `library-studio`인 별도 비관리자 계정을 준비한다. UID/GID는 DSM이 실제로 할당한 값만 사용하며 아직 미확인이다. 개인 UID1026, root, administrators(이 NAS 그룹101), docker 그룹은 금지한다. SSH 로그인/DSM 관리/다른 서비스 관리 권한은 부여하지 않는다. 비밀번호는 DSM에서만 설정하고 채팅/클라우드/GitHub로 전송하지 않는다. NAS 관리 작업자의 SSH 계정과 컨테이너 서비스 계정은 별개다.

- **원본:** 사용자가 선택한 만화 루트에 읽기/폴더 탐색만. 필요한 상위 경로의 탐색 권한을 구분한다. 다른 공유폴더는 허용하지 않는다. NAS ACL 검토/부여는 대상 계정과 경로를 확인한 뒤 DSM에서 제한적으로 수행한다. 계정만 만들면 원본을 읽을 수 있다고 가정하지 않는다.
- **앱 데이터:** 해당 Studio 프로젝트의 전용 DB/캐시/업로드/다운로드 경로에만 필요한 쓰기 권한.
- **컨테이너:** 사용자 계정 그룹 전달 없음, 관리자 그룹 추가 없음, Docker 소켓 mount 없음. 원본은 계속 읽기 전용. 폴더 작업자는 네트워크 없음/비루트/권한 상승 금지.

`check-service-account.sh preview`는 계획만 출력하고, `check`는 이름이 정확히 `library-studio`인 계정의 숫자 ID/그룹만 확인한다. 계정/ACL/파일을 만들거나 Docker/미디어를 조회하지 않는다. UID1026/root/administrators/docker 또는 요청한 UID 불일치는 거부한다. 통과는 계정 확인일 뿐 원본 접근이나 서비스 전환 성공이 아니다. 새 설치 패키지는 install 모드의 모든 쓰기 전에 이 검사를 필수로 수행한다. 최초 plan의 숫자 예시는 NAS 계정 존재를 검증하지 않는다.

## 기존 pilot 전환안과 남은 실제 NAS 단계

1. DSM에서 비관리자 전용 계정을 준비하고 읽기 전용 확인 도구로 UID/GID/그룹을 확인한다. 이 단계에서 원본이나 기존 서비스 권한을 일괄 변경하지 않는다.
2. 현재 pilot의 이미지/프로젝트/5개 볼륨/라이브러리·inbox/설정 식별자와 실제 사용량을 확인한다. 개인 파일 목록이나 비밀 값은 외부에 보내지 않는다. 전환에 필요한 여유 공간을 확인한다.
3. 기존 pilot만 잠시 정지하는 시간, NAS-local 백업 위치, 신규 전용 복사 볼륨과 목표 UID/GID를 구체적으로 정한다. 기존 원본과 기존 볼륨은 보존한다. 다른 서비스는 정지하지 않는다. 현재 초기화기는 비어 있지 않은 볼륨/기존 marker의 UID 변경을 거부하므로 `.env.nas`의 UID 숫자만 바꾸고 재시작하지 않는다.
4. 전환 전용 도구를 합성 자료로 검증한 뒤 사용자가 검토한 NAS 범위에서 실행한다. SQLite/Redis/업로드/캐시/플러그인과 설정을 NAS 안의 신규 전용 대상으로 일관되게 복사하고 신규 대상만 전용 신원으로 준비한다. 기존 원본/기존 볼륨에 재귀 chown, ACL 전체 변경, 삭제를 하지 않는다. 비밀은 NAS 안에 그대로 보존한다.
5. 신규 전용 볼륨과 전용 UID를 사용하는 구성으로 pilot 서비스만 재생성한다. health/웹 로그인/합성 자료 읽기·다운로드를 먼저 확인한다. 실패 시 신규 서비스만 중단하고 기존 볼륨/설정을 보존해 복구 대상을 검토한다. 개인 UID로 다시 실행하는 것을 자동 되돌리기로 사용하지 않는다.
6. 별도로 선택 원본의 전용 계정 읽기 권한과 RO mount를 확인하고 작은 한 폴더의 처리 방식/추가 공간을 검토한 뒤 시험한다. 거부되면 중단한다. 개인 계정/관리자 그룹/root로 우회하지 않는다.

계정 생성, NAS ACL 부여, 기존 서비스 전환, 실제 개인 자료 등록은 모두 아직 미수행이다. 필요한 NAS 접근 없이 전환 성공을 주장하지 않는다. 자동 댓글/실제 외부 사이트 다운로드와 전체 포크 이미지 정책 차단도 이전 문서의 미검증 상태를 유지한다.
