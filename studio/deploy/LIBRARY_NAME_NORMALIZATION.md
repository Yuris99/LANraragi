# Same-folder archive name normalization

`normalize-nas-library.sh apply <approved source root>` is an explicit NAS-local action. It uses the existing app-only updater to install the pinned compatible Studio runtime, backs up SQLite as the existing app user, synchronizes the catalog and fills empty, unlocked artists from filename hints. It then prepares, verifies and executes renames automatically; no separate planning command is required. The temporary executor has network disabled, a read-only root filesystem and code, one private writable report directory, and the approved source bind temporarily writable. Long-running LANraragi source mounts remain read-only. No Docker socket is mounted inside the executor.

Files remain CBZs in their current collection and subdirectory. The basename becomes `[Artist] Title [H123456] [L17].cbz`, with E/N for explicitly linked other providers. An unlinked filename number becomes U, never a source assertion. Every name includes its persistent local L number. Hitomi, E-Hentai and nhentai source priority matches library short links. The archive bytes, page order, inode, ownership and file ACL are preserved; no repacking or archive backup copy is needed. Parent directory timestamps naturally change. Directory hierarchies are retained; this is not an artist-folder relocation operation.

The initial supported collections are `manga` and `images`. Unknown artists, unmatched catalog records, mismatching basenames, symlinks, existing targets and duplicate upstream partial IDs are held. Hidden and NAS system directories are skipped. Traversal is bounded to 20000 entries, 5000 CBZs and depth 16; archives are bounded to 2GiB each. Collection symlinks, unsupported atomic rename facilities or invalid private reports reject execution. Only a full-file SHA-256 match through this instance's LANraragi download API proves the catalog/file relationship; the upstream partial content ID alone is insufficient.

The wrapper serializes against the installed deployment controller. It rejects active download/folder jobs, rechecks metadata before the first rename, and briefly stops only Studio during mutation. LANraragi keeps running. It waits for the existing watcher to update filenames, verifies full downloads under the same archive IDs, synchronizes Studio and confirms the original work IDs. Favorites, tags, source URLs, comments, local numbers and reading progress stay in the same records. Locked titles stay intact; unlocked titles continue their existing behavior of following upstream filenames. No public site is queried and no source candidate is chosen automatically.

A root-private journal and original catalog export stay under the app's private review directory. Linux `renameat2(RENAME_NOREPLACE)` makes each rename atomic and refuses a concurrent destination, including on rollback. Pending state is durable before mutation, directory changes are fsynced, and every archive is revalidated by full hash and inode. Re-running the same command resumes the same plan idempotently. Metadata changes before the first rename archive the stale private reports and require retrying the same command. External library writers must be paused; advisory locks cannot control unrelated programs.

`normalize-nas-library.sh rollback <same root>` reverses only this journal's exact renames after fresh hash/inode validation. It does not overwrite later files, recursively remove directories or undo later metadata edits. Artist registrations remain; the separate SQLite backup preserves their previous state for a deliberate full database restore if needed. The current journal is intentionally one operation, not a continually rescanning organizer. Retain it until the operation and any rollback decision are complete.

This modifies shared physical filenames. Other applications referencing those paths may need an operator-managed refresh. The wrapper never accesses or changes Stash/NMLO configuration, services or databases, changes NAS ACL, exposes ports or alters the automatic controller's enabled flag. Actual NAS execution is separate from publishing this app release and requires running the explicit local command. Do not upload the catalog, journal or backups.

Validation uses generated archives and isolated services only. Unit checks execute real renames and reversals, interruption recovery in both directions, unchanged content/inodes, collisions including concurrent targets, source changes, missing backend proof, provider priority, unresolved-number parsing, symlinks and path escape rejection. The Docker/LANraragi/Studio/Chromium rehearsal checks same-ID reindexing, existing local reader links, downloads, locked titles, favorites, comments, reading progress and rollback. The host wrapper additionally has offline preview/path/scope tests. Device-specific execution remains unverified until the operator supplies its result.
