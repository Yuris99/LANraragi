# 사이트 연결과 NAS 전용 로그인

Studio의 관리자 화면에서 NAS 전용 브라우저를 조작하고, 명시적으로 저장한 사이트별 쿠키를 NAS 외부 다운로드 작업자가 사용하는 선택 기능입니다. 일반 PC 브라우저의 로그인 상태를 자동으로 가져오지 않습니다. 업로드된 참고 프로젝트의 코드를 복사하거나 실행하지 않고 독립적으로 구현했습니다.

## 현재 범위

- `사이트 연결 · 로그인`에서 전용 브라우저를 열고 화면의 입력란을 클릭한 뒤 문자 입력, Tab, Enter 등으로 직접 로그인합니다. `로그인 후 대상 사이트 열기`로 고정된 사이트 홈을 확인할 수 있습니다.
- 한 번에 한 창, 시작 후 최대 10분입니다. 자동 로그인, 임의 URL 탐색, 일반 브라우저 프로필 읽기, CAPTCHA 해결, 프록시 우회 기능은 없습니다. 전용 브라우저는 headless Chromium이며 실제 사이트가 이를 허용하거나 지원한다는 보장은 없습니다.
- 로그인 창은 HTTPS와 해당 사이트의 명시된 도메인에만 요청합니다. 서비스 워커, WebSocket, 다른 창, 외부 다운로드는 사용하지 않습니다. 로그인에 다른 인증 도메인이나 팝업이 필요한 경우 현재 구현에서는 완료할 수 없습니다. 제한을 우회하지 말고 실제 요구사항을 확인해야 합니다.
- `로그인 완료 · 세션 저장`을 눌렀을 때만 쿠키를 저장합니다. 상태는 `세션 저장됨 · 실제 접근 미검증`입니다. 쿠키 존재만으로 로그인 성공을 판정하지 않습니다. 쿠키 외의 localStorage/브라우저 프로필은 보존하지 않습니다.
- 다운로드 작업자는 해당 사이트 세션의 시도별 비공개 복사본을 사용합니다. 엔진이 저장된 원본 세션 파일을 수정하지 못하며, 복사본은 프로세스 정상 종료 시 정리합니다. 강제 종료된 복사본은 컨테이너 임시 파일시스템에만 남고 영구 다운로드 폴더에 저장하지 않습니다.
- 유효하지 않거나 만료된 저장 세션은 익명 다운로드로 자동 전환하지 않습니다. 쿠키가 서버에서 폐기된 경우 엔진의 실제 응답을 확인해야 합니다.
- 기본 `LANraragi 서버 플러그인`에는 이 세션이 전달되지 않습니다. 세션 사용에는 **외부 다운로드 작업자**와 최신 세션 연동 이미지가 필요합니다. 작업자 접속 표시와 사이트 다운로드 성공 여부는 별개입니다.
- E-Hentai/nHentai 로그인과 Hitomi 외부 엔진의 실제 사이트 동작은 미검증입니다. Hitomi 로그인 화면은 제공하지 않습니다. ExHentai 로그인 세션 보관은 준비했지만 다운로드는 계속 비활성입니다. 고정 gallery-dl 버전의 인증 부재 시 다른 출처로 전환하는 동작을 확인했기 때문에 동일 출처 인증 검증 전에는 활성화하지 않습니다.

## 다운로드 접수와 보관함 연결

LANraragi의 `/api/download_url` 명세는 쿼리 또는 multipart 본문을 받습니다. 기존 Studio의 URL 인코딩 본문이 OpenAPI 검증에서 400으로 거절되는 문제를 클라우드의 실제 LANraragi에서 재현했습니다. Studio는 본문 없이 URL 쿼리로 접수하도록 수정했습니다. 이는 실제 사이트 다운로드 성공을 의미하지 않습니다. 기존의 원격 접수 여부 불명확 작업은 자동 재제출하지 않습니다.

외부 엔진은 완성한 CBZ를 원자적으로 게시하고 작업자는 크기·SHA-256을 보고합니다. NAS에서 완료된 작업만 백엔드의 동일 출처 파일명 후보와 전체 바이트 해시를 대조한 뒤 보관함에 연결합니다. 원래 출처 URL·댓글을 보존하며 다른 파일이나 이미 연결된 판본과 충돌하면 자동 병합하지 않고 확인 대상으로 남깁니다. PC 작업은 이 방식으로 NAS에 가져오지 않습니다. NAS 작업자의 전용 다운로드 경로가 기존 LANraragi의 **승인된 전용 앱 라이브러리 내부**에 있어야 자동 색인이 가능합니다.

## NAS 설치안

현재 Studio 코드 업데이트와 새 서비스 설치는 별도입니다. 자동 앱 업데이트만으로 새 컨테이너·권한·마운트를 추가하지 않습니다.

새 구성은 `compose.login.yaml`과 선택적인 `compose.worker-sessions.yaml`을 사용한 **별도 Compose 프로젝트**입니다.

- 기존 Studio의 전용 네트워크에만 연결합니다. 호스트 포트, Docker 소켓, 원본 NAS 폴더, Stash/NMLO 볼륨은 연결하지 않습니다.
- 로그인 키와 사이트 세션에 각각 새 전용 볼륨을 사용합니다. 상시 서비스는 현재 Studio와 같은 숫자 UID/GID로 실행하며 기존 NAS 계정의 홈·SSH 자격 증명이나 추가 그룹은 사용하지 않습니다.
- 네트워크 없는 일회성 초기화 컨테이너만 root입니다. 새 볼륨을 초기화하고 기존 전용 Studio 데이터 볼륨에 `.site-login-token`, `.site-login.json` 두 파일만 독점 생성합니다. DB를 읽거나 기존 파일의 소유권·권한을 바꾸지 않습니다. 기존 로그인 파일이 다르면 덮어쓰지 않고 중지합니다.
- 디렉터리는 0700, 세션·키·설정 파일은 0600입니다. 로그인 서비스는 Studio DB 볼륨을 받지 않습니다. 다운로드 작업자는 세션 볼륨을 읽기 전용으로 받습니다.
- 브라우저는 읽기 전용 루트, 임시 `/tmp`, 메모리 1GiB와 프로세스 수 제한을 사용합니다. Chromium은 해당 컨테이너 호환을 위해 `--no-sandbox`로 실행하므로 컨테이너 격리에 의존합니다. NAS 커널에서 프로세스 샌드박스가 검증됐다는 의미가 아닙니다.
- 작업자는 한 인스턴스, 메모리 384MiB입니다. DS718+에서 지원되지 않았던 CPU quota를 추가하지 않습니다. 작업자를 여러 인스턴스로 확장하지 마세요.
- 현재 기본 Compose·자동 업데이트 컨트롤러·기존 Studio 컨테이너 설정은 변경하지 않습니다. Studio는 전용 데이터 폴더의 두 새 파일을 동적으로 확인하므로 정상 앱 재생성 후에도 연결을 유지합니다.
- 별도 HTTP 프록시가 설정된 NAS에서는 내부 `site-login`/`studio` 통신의 정상 경로를 별도 확인해야 합니다. 기존 프록시 설정이나 네트워크 정책을 자동 변경하지 않습니다.

`deploy/install-site-login.sh`는 같은 번들의 Compose 파일과 이미 로드된 고정 이미지 ID를 사용합니다. 인수는 다음 순서입니다.

```text
preview|apply-login|start-worker|status APP_ROOT APP_PROJECT LOGIN_IMAGE WORKER_IMAGE
```

`preview`는 서비스·전용 볼륨·전용 다운로드 경로·이미지 존재를 읽기 전용으로 확인합니다. `apply-login`은 로그인 서비스만 시작합니다. **`start-worker`는 별도 명령이며 기존 대기 중인 NAS 외부 엔진 작업을 실행할 수 있습니다.** 실제 사이트 검증과 사용자 승인을 분리해야 합니다. 일반 NAS 원본을 이동·삭제하거나 공개 인터넷으로 포트를 열지 않습니다.

## 백업·복원·해제

SQLite 백업과 메타데이터 내보내기는 로그인 세션을 포함하지 않습니다. 로그인 키 볼륨·세션 볼륨·Studio 데이터의 두 로그인 파일은 민감 정보이므로 필요한 경우 NAS 내부의 비공개 백업에 함께 보관하세요. 클라우드·GitHub·채팅으로 보내지 마세요. 쿠키를 다른 환경으로 복원해도 사이트가 세션을 인정한다는 보장은 없습니다.

복원은 같은 UID/GID와 서로 일치하는 서비스 키를 사용해야 합니다. 초기화는 기존 키를 자동 재발급하거나 서로 다른 연결 파일을 덮어쓰지 않습니다. 단순 서비스 재시작은 저장된 세션과 출력 폴더를 유지합니다. 작업자 중단으로 임대가 만료된 다운로드는 자동 재실행하지 않고 결과를 확인한 뒤 재시도합니다.

사이트별 해제는 화면의 `저장 세션 해제`를 사용합니다. 전체 기능을 끌 때는 별도 로그인 프로젝트의 서비스만 중지하고 볼륨을 보존합니다. Studio의 `.site-login.json`을 NAS에서 명시적으로 제거하면 설치 전 상태 표시로 돌아갑니다. 원본 미디어·DB를 삭제하거나 이전 판본 정리 스크립트를 다시 실행할 필요가 없습니다.

## 검증

- `python -B -m unittest discover -s studio/tests -v`
- `PYTHONPATH=studio python -B studio/tests/site_login_smoke.py`
- `PYTHONPATH=studio python -B studio/tests/site_login_container_smoke.py`
- 기존 `editions_smoke.py`, `navigation_smoke.py`와 JS 구문 검사

로그인 스모크는 실제 Chromium과 Studio/RPC를 사용하되 로그인 사이트 응답과 계정·쿠키는 전부 합성입니다. 컨테이너 스모크는 실제 NAS용 Compose·작업자·LANraragi를 사용하되 외부 사이트 추출기만 합성 엔진으로 바꿉니다. 이를 실제 E-Hentai/ExHentai/Hitomi/nHentai 성공이나 실제 NAS 설치 완료로 해석하면 안 됩니다.
