# LANraragi Studio — Orca 인수인계 및 진행 분석

기록일: 2026-10-24 (Asia/Seoul). 이 문서는 대화 기록, 현재 코드, 배포 명세와 남아 있는 검증 로그를 대조한 인수인계다. 이번 변경은 문서 정리이며 앱이나 NAS를 새로 배포하지 않는다.

## 1. 다음 세션에서 먼저 알아야 할 상태

## 2. 사용자 목표와 반드시 유지할 결정

- Synology DS718+에서 개인 만화 라이브러리를 관리한다. Stash의 관리 편의성을 참고하되 Studio 독자 UI를 사용한다.
- 한 작품의 여러 출처를 연결하되 사이트별 ID, 전체 URL, 제목 변형, 태그, 댓글 원본을 보존한다. **같은 숫자라는 이유로 같은 작품으로 연결하거나 파일을 병합하지 않는다.**
- 한 사이트의 기준 URL을 등록하면 다른 출처를 백그라운드에서 찾는 것이 원하는 기본 흐름이다. 작품마다 HTML을 저장하거나 수동 조회 버튼을 반복하게 만드는 방식으로 되돌리지 않는다.
- 기본 썸네일은 **블러**다. 픽셀 모자이크가 아니다. 상세/리더는 원본이며 블러 on/off를 저장한다. 썸네일은 전체 비율을 유지한다.
- 상세와 리더 각 페이지에 주소·브라우저 방문 기록이 있어야 한다. 뒤로/앞으로로 페이지를 이동한다.
- 즐겨찾기, 작가 등록, 사용자 태그, 태그 필터·자동완성을 유지한다. ‘아직 읽지 않은 작품’ 메뉴는 제거했다.
- 번역본·수정본·보이스코믹 판본을 별도로 유지하고 필요하면 같은 작품 묶음으로 수동 연결한다. 동인음성 전용 Studio는 별도 파생 프로젝트 범위다.
- 업로드/다운로드와 PC/NAS 저장 대상은 제공한다. 저장소 직접 연결을 선호하며 기존 폴더 사본 만들기를 기본 작업으로 다시 제시하지 않는다.
- 세션은 **파일 또는 복붙**으로 등록한다. 현재 사용자가 편하게 쓸 경로는 내보낸 JSON을 Studio에 붙여 넣는 방식이다. 비밀번호·쿠키를 채팅으로 요구하지 않는다.
- 사용자는 반복 SSH 명령을 싫어한다. 기존 Studio 전용 자동 배포 채널을 사용하고, 새 수동 단계가 필요하면 기술적으로 왜 필요한지 설명한다.
- 업데이트 보고에는 **Studio 배포 번호 / 변경 내용 / NAS 적용 확인 여부**를 함께 적는다. LANraragi 0.9.x와 Studio 업데이트 번호는 다른 값이다.

### 실제 NAS에서 사용자 결과로 확인된 이력

- Studio·LANraragi healthy, SSH 터널 접속·Studio 로그인과 일부 열람 동작이 확인됐다.
- 원래 위치 아카이브 변환: **324개 검증 / 원본 폴더 324개 제거 / 오류 0**이라는 사용자 실행 결과가 있다. 전체 바이트 검증 뒤 제거하는, 당시 명시 승인된 작업이다.
- 사본 정리: **11개 메타데이터 병합 및 검증 사본 11개 제거, originals_modified=0**, Studio catalog 접근 성공이라는 사용자 결과가 있다. 롤백 백업은 보존됐다.
- 과거 화면에 336개가 보였다는 사용자 응답이 있으나, 위 정리 전후를 합산해 현재 권수를 추정하지 않는다.
- 위 이력은 과거의 승인·결과이며, 다음 세션에 삭제·변환·권한 변경을 다시 수행할 포괄 권한이 아니다.

## 4. 사이트별 현재 상태

| 사이트 | 정보·댓글 경로 | 로그인 세션 | 파일 다운로드 |
| --- | --- | --- | --- |
| E-Hentai | HTML 메타데이터·태그·댓글 + 일반 제목 검색 구현 | NAS 세션 사용, 명시적 PC 내보내기 파일/복붙 등록 구현. 세션 없으면 공개 비로그인 요청 가능 | gallery-dl / 설치된 서버 플러그인 경로 있음. 실제 성공 미확인 |
| ExHentai | 별도 provider, 자기 사이트 HTML·검색 경로 | 자기 세션이 없으면 요청 중지. 다른 도메인 세션으로 자동 대체하지 않음 | **명시적 비활성**. 자동 E-Hentai fallback 방지. 검증 없이 켜지 않음 |
| Hitomi | 고정 galleryinfo JS + 작가 공개 nozomi 색인 | Studio 로그인 기능 없음. 계정 로그인 없이 공개 정보 접근 경로 | gallery-dl 후보 어댑터 있음. 실제 다운로드 미확인. 기존 NAS 서버 플러그인이 없다는 사용자 오류 이력 |
| nHentai | 별도 출처와 JSON 댓글 커넥터 | NAS 로그인 경로는 있으나 이번 PC 세션 가져오기는 EH/Ex 한정 | 외부 엔진 후보, 실제 성공 미확인. EH/Ex/Hitomi 자동 연결 3사이트에는 포함되지 않음 |

E-Hentai의 과거 HTTP400은 LANraragi 요청 본문 형식 문제를 재현하고 수정한 이력이 있다. 그러나 이는 실제 사이트 다운로드 성공의 증거가 아니다. 원격 접수 여부를 모를 때는 자동 중복 제출하지 않는다.

`/api/health`의 comment_fetch/metadata_fetch 요약 문자열에는 최신 ExHentai 항목이 충분히 반영되지 않은 부분이 있다. 실제 지원 표시는 이 문서와 현재 코드 경로를 대조하고 다음 기능 변경 때 정합성을 보완한다.

`연결 확인 필요`만으로 쿠키 미등록·차단·DNS·서비스 불능 중 하나를 단정하지 않는다. 사이트 연결 화면의 세션 상태와 최근 요청 모드/HTTP 상태를 함께 본다. `저장 세션 사용`도 서버 로그인 유효성 검증이 아니라 요청에 해당 쿠키를 적용했다는 의미다. HTTP200은 인증 페이지일 수도 있다.

## 5. 중요한 코드 경로와 설계

| `auto_sources.py` | 작업 epoch/임대/검색 위치/후보 보존, 지연·회로·중지·세션 변경 감지 |

| `login_service.py` | 기존 전용 서비스의 일반 Chromium/X11 및 인증 RPC. GUI 새 포트 없이 동작 |
| `gallery_engine.py`, `worker.py` | 외부 엔진 명령, 시도별 디렉터리, 세션 스냅샷, heartbeat/보고, 검증·게시 |
| `editions.py` | 독립 판본/음성 자산/큐·재생 진행·표지 지문 |
| `backup.py` | SQLite만 백업·복원. 파일·Redis·세션을 자동 포함하지 않음 |
| `web/app.js`, `web/index.html`, `web/style.css` | UI. 입력 폼과 재생기를 백그라운드 갱신이 교체하지 않도록 유지 |
| `deploy/` | 고정 NAS 설치/업데이트·변환·정리/복구 도구. 이름이 apply라고 해서 실행하지 말 것 |

### 자동 출처 연결의 경계

- EH/Ex 검색 결과는 묶음 5개와 다음 페이지, Hitomi는 **첫 작가 색인** 8개씩 진행한다. 모든 별칭/제목 색인 검색은 아니다.
- 제목 정규화, 공통 작가·언어, 알려진 페이지 수 일치, 태그 Jaccard ≥0.7인 유일 후보만 검색 완료 뒤 연결한다. 여러 후보/정보 부족/언어 차이는 확인 대상으로 남긴다.
- 실행기 1개, 요청 전 3초 간격, 묶음 사이 10초. 사이트 실패는 30분 대기 회로, 작업 연속 5회 실패 뒤 대기한다. 임대 만료와 기준 epoch 변경 시 이전 결과를 쓰지 않는다.
- 연결은 파일 다운로드·합치기·삭제·판본 묶기를 실행하지 않는다. 상세: [AUTOMATIC_SOURCES.md](AUTOMATIC_SOURCES.md).

### 세션 등록의 경계

- Studio 사이트 연결 화면에 내보낸 JSON/Netscape를 붙이거나 파일로 고른다. 둘을 동시에 입력하면 하나를 선택하도록 요청한다.
- EH/Ex 계정 인증 쿠키만 허용, 최대128KiB/500개. 다른 도메인/만료/형식 오류는 기존 세션을 보존하며 거절한다. 두 사이트 프로필은 별개다.
- NAS 0700 디렉터리/0600 파일. 관리자로 인증된 같은 출처 요청만 등록 가능. 작업자 토큰은 불가.
- Cloudflare 보안 확인 쿠키는 가져오지 않는다. 브라우저 프로필·비밀번호 저장소 자동 추출, CAPTCHA 풀이·위장 없음.
- 입력은 제출 성공/실패/창 닫기 때 비운다. 쿠키 값은 로그·카탈로그·내보내기·localStorage에 넣지 않는다. 최근 요청 진단은 재시작 때 초기화된다.
- 이 vault의 세션을 metadata RPC와 엔진용 private snapshot에 사용한다. 등록 성공이 다운로드 엔진 지원 보증은 아니다. 상세: [SESSION_IMPORT.md](SESSION_IMPORT.md).

### 단축 주소와 판본

기본 숫자=Hitomi, E=E-Hentai, X=ExHentai, N=nHentai, L=로컬 번호. 리더 페이지는 `/#/E123/6` 형태다. 과거 ExHentai를 E로 저장했던 데이터는 출처를 분리하고 제한적으로 옛 별칭을 보존한다. 같은 번호로 출처를 추정하지 않는다. 같은 출처 URL을 여러 판본으로 자동 재배치하지 않는다.

## 6. Orca에서 이어갈 우선순위와 완료 기준

### P0 — 현재 NAS 적용 및 정상 세션 경로 검증

1. 브랜치 최신 HEAD 확인 → 이 문서 → README → AUTOMATIC_SOURCES → SESSION_IMPORT → 관련 코드 순서로 읽는다. 예전 CLOUD_HANDOFF는 역사 기록이며 현재 상태표를 대신하지 않는다.
2. 현재 화면 맨 아래 `Studio 업데이트 20`을 확인한다. LANraragi 0.9.x를 Studio 번호로 읽지 않는다. 서비스 5의 `session_import` 기능 여부와 저장 세션 상태도 확인한다. NAS 결과를 직접 읽을 권한/경로가 없다면 미확인으로 둔다.
3. 사용자가 정상 접근 가능한 EH/Ex에서 직접 내보낸 세션을 **NAS Studio로만** 붙여 넣는다. 채팅·GitHub·클라우드 개발 파일로 전송하지 않는다. Studio는 PC 브라우저의 세션을 몰래 읽지 않는다.
4. 정상 권한의 적법한 테스트 자료 하나로 정보 조회를 확인한다. 성적 콘텐츠라면 등장인물이 모두 성인임이 확인된 자료로 제한한다. 적절한 테스트 대상을 확보하지 못하면 꼭 필요한 URL만 요청하고 합성/실제 결과를 분리한다.
5. 성공 기준: 대상 사이트 세션 적용 + 실제 작품 메타데이터 파싱 + 원래 로컬 제목 보존 + 출처별 태그/댓글 보존. 인증 페이지/403/429면 중지·명시 오류. 쿠키 자체와 개인 제목/본문은 보고서에 넣지 않는다.

### P1 — 자동 연결 및 실제 다운로드를 각각 끝까지 검증

- 한 기준 URL만 등록해 반대 사이트 검색 → 고유 후보 연결/모호 후보 보류 → 댓글 갱신이 실제 응답에서도 작동하는지 확인한다. 언어가 다른 번역본은 자동 동일 판본 취급하지 않는다.
- Hitomi 작가 색인의 누락/별칭 한계를 측정하고, 필요하면 정상 공개 검색 범위에서 개선한다. 번호나 비슷한 업로드 시각만으로 조건을 느슨하게 만들지 않는다.
- EH/Hitomi는 허용된 엔진으로 실제 최소 다운로드 → 유효 이미지/CBZ → NAS 게시 → LANraragi 색인 → Studio 리더·원본 다운로드·해시 확인까지 하나의 증거로 남긴다. PC 대상은 실제 PC 작업자에서 별도 확인한다.
- ExHentai는 동일 출처 인증·redirect/fallback 차단을 검증할 설계와 테스트가 준비되기 전 engine 비활성 상태를 유지한다. 접근 거부 자료를 다른 사이트에서 대신 얻으려 하지 않는다.
- 작업자 중단/재시작/임대 만료/재시도 시 기존 원격 작업과 시도별 출력 보존, 중복 제출·중복 파일 방지를 검증한다. detached 자식 프로세스 자동 복구는 완료로 표시하지 않는다.
- 사이트별 결과를 성공/실패/미검증으로 명시한다. ‘세션 저장됨’, ‘작업 접수됨’만으로 성공 보고하지 않는다.

### P2 — 기존 라이브러리 번호·작가·저장 규칙 마무리

- 현재 실제 카탈로그의 작가/번호 누락·충돌을 NAS 안에서만 집계한다. 이전 변환·사본 삭제를 다시 시작하지 않는다.
- 확인된 작가와 출처만 정규 파일명에 반영한다. 정규 이름은 `[작가] 제목 … .cbz`를 기본으로 `sources.canonical_archive_name`과 고정 NAS 도구를 함께 확인한다. DB/아카이브 ID/북마크 연결을 검증하고 이름만으로 파일을 덮어쓰지 않는다.
- 현재 통일 상태와 보류 건수를 확인한 뒤 필요한 변경 범위를 구체적으로 준비한다. 개인 원본 이동/삭제/추가 권한 변경은 새 작업의 승인 범위를 확인한다.

### P3 — 실사용 운영 마감

- 실제 DS718+에서 대량 목록·태그·썸네일·보이스코믹 재생과 메모리/응답 시간을 측정한다. 제공 benchmark는 클라우드 수치와 구분한다.
- Studio SQLite + LANraragi Redis + 아카이브/음성 자산 + 로컬 설정/세션의 별도 백업 정책을 준비하고 **격리된 새 목적지**에서 복구를 확인한다. 운영 DB를 덮어쓰며 시험하지 않는다.
- 업그레이드/중단/재개/롤백 후 전체 연결·읽기 위치·판본·댓글 보존을 확인한다. 기존 세션·미디어 보존을 포함해 완료 기준을 남긴다.
- 외부 역이미지 검색 자동 API, 독립 동인음성 프로젝트는 별도 요구로 진행한다. 현재 수동 검색 보조를 완전 자동 검색으로 표시하지 않는다.

## 7. 검증 증거와 재현

### 기존에 실제로 확인한 범위

- `c8d95df5` 세션 등록 코어의 **337개** 표준 unittest/HTTP/회귀 검사 통과 기록이 남아 있다. 이는 최신 문서 HEAD 전체에 오늘 새로 돌린 테스트라는 뜻이 아니다.
- 이후 세션 붙여넣기 및 버전 표시 변경은 실제 Studio + 인증 로그인 RPC + Chromium으로 검증했다. 파일/복붙 성공, 잘못된 입력의 기존 세션 보존, 성공/실패/창 닫기 초기화, 값의 UI/localStorage 노출 방지, 진단 표시를 포함한다.
- 앱 20 버전은 실제 런타임 API 값이며, 별도 LANraragi 0.9.81 표시/백엔드 연결 실패/모바일 표시가 확인됐다. 해당 변경의 배포 보호 검사 **17개**, JS 구문·diff 검사 통과.
- 기존 독립 Docker 검증에는 실제 LANraragi 0.9.81과 합성 CBZ의 썸네일·페이지·전체 다운로드 해시, 비루트 서비스, 전용 볼륨, 원본 RO, 서비스 재시작·코드 롤백 보존 등이 있다. 각 과거 문서는 당시 배포 번호와 범위를 기록한 것이며 최신 NAS 완료 증거는 아니다.
- 참고 로그는 기존 작업 환경의 `work/session-import/` 아래 regression-complete.log, version-browser.log, version-deployment.log 등에 있었다. **Orca로 자동 이전되지 않는다.** 커밋되는 것은 아래 재현 코드와 요약이며, 과거 개인 HTML/미디어를 로그 확보 목적으로 올리지 않는다.

## 8. 환경·권한·배포 인계

- 현재 개발은 독립 LANraragi 체크아웃이다. **NMLO 저장소/코드·기존 Stash는 수정하지 않는다.** NMLO는 관리형 VPN/런타임만 재사용한다. Stash의 개인 미디어를 탐색하지 않는다.
- DS718+ x86_64, 사용자 제공 DSM7.4 build90075, Container Manager24.0.2-1606, Docker server24.0.2, Compose2.20.1, 약16GB RAM이 확인된 이력이 있다. 이후 버전 변화는 다시 확인한다.
- NAS Studio는 기존 loopback 바인딩/SSH 터널을 유지한다. 공개 노출·방화벽·NAS 계정/ACL·예약 작업 변경을 이 문서가 승인하지 않는다. 원본 경로·비밀번호·쿠키·DB·미디어는 여기 적거나 GitHub로 옮기지 않는다.
- 기존 설치의 Studio UID/GID1026:100, 사용자 승인으로 LANraragi 원본 reader UID/GID0:0 및 source RO라는 운영 이력이 있다. root reader와 전용 앱 출력 권한을 혼동하거나 새 원본 ACL을 재귀 수정하지 않는다.
- NAS 커널은 CPU CFS quota/NanoCPUs를 지원하지 않아 cpus 항목을 제거한 이력이 있다. 메모리 제한/동시 실행 1은 유지한다. 새 Compose 기본값을 기존 NAS에 무조건 덮어쓰지 않는다.
- 앱 업데이트는 `deploy/nas-release.json` → 기존 고정 NAS-local pull controller, 로그인·작업자는 별도 **desktop** 서비스 manifest 경로다. 기존 컨트롤러/레시피/Compose는 앱 소스 배포로 임의 교체할 수 없다.
- 앱의 코드·manifest와 명세 revision/hash를 먼저 공개 고정 커밋으로 검증한 뒤 generation을 올린다. 다음 앱 번호는 현재 원격 값을 다시 확인해 정하며, 변경 시 `STUDIO_UPDATE`도 함께 올린다. 문서만 바꿀 때는 앱 번호·release를 올리지 않는다.
- 현재 관리형 런타임은 connected, HTTP restricted/enforced, 설정 VPN=true, TCP grants 비어 있음, configured secrets=0으로 관측됐다. 이는 NAS 관리 접속이나 대상 사이트 접근 성공의 증거가 아니다.
- 외부 사이트 도메인의 허용은 현재 클라우드에 없다. 최소 정보 조회 대상은 e-hentai.org, exhentai.org, ltn.gold-usergeneratedcontent.net의 HTTPS이며 다운로드는 별도 실제 엔진의 필요한 호스트를 근거로 좁혀야 한다. 정책 수정은 관리형 설정 절차로만 한다.
- 전체 포크 이미지의 과거 Alpine/cpanmin.us CONNECT403은 정책 차단이었다. 해결 완료로 기록할 새 빌드 증거가 없다. 프록시/CA를 유지하고 Tailscale 직접 실행, auth key 읽기·출력, 프록시/차단 우회를 하지 않는다.
