# 등록 후 자동 출처 연결

이 문서는 이전 `SOURCE_METADATA.md`의 버튼 실행·최신 8개 한정 검색을
대체하는 현재 동작을 설명한다. 목표는 이헨·익헨·히토미 중 한 곳의 작품
URL을 연결하면 나머지 출처를 백그라운드에서 확인하는 것이다. HTML
붙여넣기나 작품마다 조회 버튼을 누르는 것이 기본 절차가 아니다.

## 등록부터 연결까지

1. 새 출처 등록 또는 원본 메타데이터 변경이 영속 SQLite 작업을 만든다.
   이미 출처가 있는 기존 작품도 최초 실행 때 대기열에 등록된다. 출처가
   없는 작품은 번호만으로 사이트를 단정하지 않고 기준 URL을 기다린다.
2. 실행기 하나가 기준 출처의 제목·작가·언어·태그·페이지 수를 읽는다.
   이미 연결된 다른 출처도 필요한 정보와 댓글을 자기 출처에 수집한다.
3. 이헨·익헨에서는 각각 자기 사이트의 일반 제목 검색을 수행하고 결과를
   5개씩 읽으며 다음 검색 페이지로 이어간다. 히토미에서는 첫 작가의
   공개 색인을 8개씩 읽고 다음 위치를 저장해 계속 진행한다.
4. 페이지/색인 진행 중에는 연결을 확정하지 않는다. 검색을 마친 뒤 제목
   정규화 결과가 같고, 작가·언어가 겹치며, 알려진 페이지 수가 같고,
   태그 Jaccard 유사도가 0.7 이상인 유일 후보만 자동 연결한다.
5. 여러 후보·번역 언어 차이·부족한 근거·다른 작품이 소유한 출처는 확인
   대상으로 남긴다. 상세 화면이 결과를 자동 갱신하고 후보 선택을 제공한다.

출처 연결은 파일 병합·이동·삭제·중복 다운로드나 판본 통합을 실행하지
않는다. 원래 작품명·사용자 태그·즐겨찾기·읽기 기록은 보존한다. 원본
태그·번호·URL·댓글과 제목 변형은 각각의 출처에 보존한다. 날짜가 비슷하거나
번호가 같다는 이유로 자동 연결하지 않는다. 이 자동 작업은 파일 다운로드를
실행하지 않는다. 익헨 다운로드 엔진은 동일 출처 동작을 실제 검증할 때까지
계속 비활성이다.

히토미 검색은 작가 색인 방식이므로 작가 누락·별칭·색인 누락이 있으면
찾지 못할 수 있다. 현재 모든 작가 별칭/전체 제목 색인 검색은 아니다.
안전 상한은 작가 색인 위치 100000, 이헨 계열 검색 페이지 1000이다.
상한·변경된 응답·접근 제한은 검색 완료/부재로 처리하지 않는다. 제목과
메타데이터 비교는 동일한 이미지 내용의 증명이 아니므로 완전히 같은
메타데이터를 공유하는 수정본은 오판할 수 있다. 엄격한 조건을 유지하고
자동 연결을 보기 설정에서 중지할 수 있다.

## 익헨과 인증

이헨과 익헨은 별도 provider이며 같은 번호도 별도 출처다. 기존 익헨 URL이
이헨 provider로 저장돼 있으면 URL과 원본 정보를 보존하면서 분리한다.
익헨 단축 주소는 `X번호`다. 실제 이헨 출처가 없는 경우에만 기존 익헨의
옛 `E번호` 북마크를 유지한다. 실제 이헨이 등록되면 `E번호`는 이헨만 가리킨다.

로그인 서비스는 새 `source-document` 내부 RPC를 제공한다. 고정된
작품/검색/메타데이터/작가 색인 HTTPS 경로만 읽으며, 익헨은 저장된 자기
세션이 없으면 요청하지 않는다. 세션 쿠키는 NAS 로그인 서비스 안에서만
사용하고 Studio에는 문서 응답만 전달한다. 사이트의 리다이렉트·제한·오류를
다른 호스트로 대체하거나 익명 요청으로 재시도하지 않는다. `cf_*`/`__cf*`
인증 확인 쿠키는 저장·전달하지 않는다. CAPTCHA 자동화나 브라우저 위장도 없다.

`source-document`는 Studio의 브라우저 로그인 조작 API에서 차단되어 있으며,
백엔드와 로그인 서비스 사이의 전용 인증 경로에서만 사용한다. 응답에는
쿠키 파일이나 키를 포함하지 않는다. 저장된 세션은 실제 접근 성공의 증명이
아니다. 만료·접근 거부는 대기로 남기고, 로그인 세션 또는 서비스 기능이
변경되면 대기 작업을 자동으로 깨운다. 아직 구버전 로그인 서비스라면 익헨은
업데이트 대기로 표시된다. 이헨·히토미의 공개 정보 조회는 기존 경로를 사용할
수 있지만 실패한 인증 요청을 익명 경로로 대체하지는 않는다.

## 자원·복구·배포

- 동시 실행 1개, 외부 요청 전 3초 간격, 묶음 사이 10초 대기다.
- 작업별 임대와 기준 정보 epoch를 저장한다. 재시작/만료 뒤 재접수하고,
  다른 실행기나 오래된 기준의 결과는 저장하지 않는다. 자동으로 추가한
  출처는 같은 작업을 재귀 생성하지 않는다.
- 접근 실패는 사이트 전체에 30분 대기 회로를 적용해 작품마다 같은 차단
  요청을 반복하지 않는다. 작업은 지수 간격으로 재시도하며 연속 5회 실패
  뒤 대기한다. 진행이 정상인 검색 묶음은 이 실패 횟수에 누적하지 않는다.
- 설정에서 중지하면 새 접수와 진행 중 결과 저장을 멈춘다. DB 복원은
  자동 작업을 차단하고 자동 연결을 끈다. 소스/검색 위치/후보는 보존한다.
- UI는 출처/태그 영역만 갱신하며 열린 편집 폼이나 재생기를 교체하지 않는다.
- 앱 코드는 기존 앱 자동 업데이트 채널을 사용한다. 로그인/작업자 소스는
  기존 desktop 서비스 채널의 다음 generation으로 빌드한다. 고정 Dockerfile,
  Compose, UID, 포트, 볼륨, 키, 예약 작업은 바꾸지 않는다. 새 수동 설치나
  원본 미디어 접근 확대가 필요하지 않다.

## 검증 경계

`test_auto_sources.py`는 한 URL 등록 후 세 출처 연결, 다른 언어 보류, 기존
연결 정보 수집, 검색 페이지/색인 재개, 두 유사 후보 보류, 옛 익헨 분리,
임대·epoch 충돌, 일시정지, 사이트 차단 회로, 백업/복원과 인증 RPC를 합성
자료로 확인한다. `auto_sources_smoke.py`는 실제 Studio HTTP 서버와 백그라운드
실행기, Chromium에서 한 URL 등록만으로 세 출처가 연결되는지 확인한다.
실제 외부 사이트 응답을 사용하는 검증과 NAS 적용 성공은 별도다.

최종 회귀 테스트 332개, 실제 Chromium 자동 연결 흐름과 기존 HTML 가져오기
흐름, JS 구문 및 배포 파일 해시 검증이 통과했다. 이 결과는 합성 사이트
응답에 대한 검증이며 실제 사이트 인증 성공을 뜻하지 않는다.

DB 변경은 테이블 추가와 기존 익헨 출처 분리이며 기존 자료를 삭제하지
않는다. 구버전 코드로 되돌리면 새 대기열은 실행되지 않고 새 X주소를
인식하지 못할 수 있다. 출처를 이헨으로 다시 합치는 역마이그레이션은
자동 실행하지 않는다. 배포 전 DB 백업을 유지하고 수정 버전으로 갱신한다.

현재 클라우드의 사이트 도메인은 허용되지 않아 실제 이헨·익헨·히토미의
정상 인증·자동 수집·다운로드 성공은 확인하지 못했다. 최소 메타데이터
검증 대상은 `e-hentai.org`, `exhentai.org`,
`ltn.gold-usergeneratedcontent.net`의 HTTPS다. NAS 정책은 별도이며, 이 문서는
도메인 허용이나 실제 로그인 완료를 의미하지 않는다. 개인 HTML·쿠키·DB·
미디어는 GitHub에 포함하지 않는다.
