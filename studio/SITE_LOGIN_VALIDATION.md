# 로그인 및 다운로드 접수 검증 기록

## 완료

- 표준 라이브러리 테스트 278개 통과. 도메인 격리, 0600/0700 권한, 세션 만료·재시작·해제, 원본 세션 보존, 비관리자·작업자·교차 출처 요청 거절, 기존 DB 보존 초기화, 중복 접수 방지와 출처·댓글 보존을 포함합니다.
- 실제 Studio·로그인 RPC·Chromium 두 개로 합성 로그인, 입력 전송, 명시적 세션 저장, 엔진용 비공개 복사본, 해제, 데스크톱·모바일 화면 검증을 통과했습니다. 실제 사이트 접속·계정은 사용하지 않았습니다.
- 별도 합성 Docker NAS 프로파일에서 비루트 로그인 브라우저, 읽기 전용 루트, 전용 볼륨 초기화, 로그인 서비스 재시작, 실제 작업자 임대·완료 보고, CBZ 원자 게시, 실제 LANraragi 색인, 전체 파일 해시 대조, 원본 출처 연결, Studio 재생성 후 연결 보존을 통과했습니다. 외부 사이트 추출기는 합성 엔진으로 대체했습니다.
- 기존 판본·보이스코믹·내부 이미지 검색·외부 수동 검색 화면 및 리더 페이지 뒤로/앞으로 이동 스모크 통과.
- JS 구문·셸 구문·diff 검사 통과.
- Debian 기반 로그인 이미지와 세션 연동 작업자 이미지 빌드 완료. 공개 CA를 BuildKit 읽기 전용 secret으로 전달하고 기존 프록시와 TLS 검증을 유지했습니다. 별도의 전체 LANraragi 포크 이미지 빌드 차단이 해결됐다는 의미는 아닙니다.

## HTTP 400 재현

클라우드의 실제 LANraragi에서 기존 URL 인코딩 본문을 보내면 OpenAPI가 `Expected multipart/form-data - got application/x-www-form-urlencoded`로 거절하는 것을 확인했습니다. 본문 없는 요청은 이 검증을 통과해 컨트롤러의 URL 누락 오류까지 도달했습니다. 다운로드 접수는 완전한 URL을 쿼리로 전달하도록 수정했고 작업 접수·상태 조회·완료 보고 경로를 회귀 테스트했습니다. 실제 사이트 파일을 다운로드한 것은 아닙니다.

## 남은 검증과 설치

- E-Hentai/Hitomi/nHentai의 실제 다운로드 및 실제 계정 인증: 미검증.
- ExHentai 다운로드: 비활성. 인증 부재 시 출처가 바뀌는 엔진 동작을 실제 고정 버전 소스로 확인했으며 활성화하지 않았습니다.
- 실제 사이트 댓글 수집: 이번 변경으로 지원 범위가 늘지 않았습니다.
- DS718+ 현지 브라우저·메모리·네트워크·사이트 호환성: 미검증.
- 실제 NAS 로그인 프로젝트·새 전용 볼륨 설치: 수행하지 않았습니다. 검토 가능한 Compose, 범위 확인 설치 도구와 이미지 후보를 준비했습니다.
- 기존 Studio 자동 업데이트는 앱 코드만 배포합니다. 새 서비스 설치와 외부 작업자 시작은 별도의 NAS 현지 승인 단계입니다.

## 재현 방법

`SITE_LOGIN.md`의 검증 명령을 사용합니다. Docker 스모크에는 기존 합성 NAS 기본 이미지와 새 로그인/작업자 이미지 후보가 필요합니다. 모든 자료는 생성된 테스트 자료이며 외부 사이트 응답·계정·쿠키·개인 원본을 사용하지 않습니다. 원래 NAS 이미지와 바이트가 동일한 기본 이미지로 검증했다는 의미는 아닙니다.

검증 중 클라우드 작업 디스크 부족으로 실패한 실행은 제외했습니다. 종료된 기존 합성 컨테이너만 정리해 공간을 확보한 뒤 다시 검증했습니다.
