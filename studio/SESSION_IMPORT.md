# PC 로그인 세션 직접 등록

Studio의 **설정 → 사이트 연결 · 로그인 → PC에서 내보낸 로그인 세션 등록**에서 E-Hentai 또는 ExHentai를 선택하고 사이트 전용 JSON 배열 / Netscape cookies.txt를 등록한다. PC에서 해당 사이트에 정상 로그인한 사용자가 명시적으로 내보낸 파일만 사용한다. 브라우저 프로필·비밀번호 저장소를 자동 추출하지 않는다. 파일은 PC에서 현재 연결한 Studio와 NAS 로그인 서비스로 전송되며 GitHub나 개발 클라우드로 업로드하지 않는다. 세션 파일은 계정 인증 정보이므로 채팅에 첨부하지 않는다. 기존처럼 SSH 터널의 localhost 주소나 신뢰하는 HTTPS 연결로 이용한다.

JSON은 쿠키 객체 배열이며 domain, name, value, path, secure, httpOnly와 expires 또는 expirationDate를 읽는다. Netscape 형식은 7개 탭 필드 및 HttpOnly 접두사를 지원한다. 사이트 전용 파일, 최대128KiB/500개를 허용한다. 다른 사이트 도메인이 포함되거나 로그인 쿠키가 없거나 만료됐다면 등록을 거절하고 기존 세션을 보존한다. 대상 사이트 루트 도메인의 ipb_member_id/ipb_pass_hash가 필요하며 igneous도 저장할 수 있다. Cloudflare 인증 쿠키와 기타 설정 쿠키는 가져오지 않는다. E-Hentai와 ExHentai 세션은 별도이며 도메인을 바꾸거나 다른 사이트용 쿠키를 복제하지 않는다.

저장은 기존 NAS 전용 0700 디렉터리/0600 파일을 사용한다. 관리자로 인증한 같은 출처 요청만 허용하며 다운로드 작업자 토큰은 등록할 수 없다. 응답·로그·카탈로그·메타데이터 내보내기·localStorage에 쿠키 값을 넣지 않는다. 파일 입력은 등록 완료/실패/창 닫기에 비운다. 브라우저 메모리의 즉시 완전 소거를 보장하는 기능은 아니다.

등록된 세션의 변경은 기존 자동 연결 작업의 재확인을 유도한다. 사이트 연결 화면의 최근 정보 조회는 비로그인 / 요청 주소에 맞는 저장 세션 사용 / 적용되는 쿠키 없음 / 요청하지 않음을 구분한다. HTTP 접근 제한·연결 실패·응답 수신도 구분하되 **저장 또는 HTTP200을 로그인 유효성 검증으로 표시하지 않는다**. 기록은 URL/본문/쿠키 없이 상태와 시각만 메모리에 보관하며 서비스 재시작 시 초기화된다. 추가 인증·403·429 등은 우회하지 않으며 인증 실패 뒤 다른 출처로 재시도하지 않는다.

실제 계정 세션을 쓰는 라이브 사이트 검증은 미실시다. 합성 파일로 JSON/Netscape, 만료/오류 시 기존 파일 보존, 도메인·쿠키 필터링, 실제 Studio→인증 RPC→NAS 전용 파일 경로, 관리자/동일 출처 제한, 상태 비밀 값 제외를 검증한다. 실제 Chromium에서 파일 선택/등록/입력 초기화/상태 표시를 별도 검증한다. 이는 실제 사이트 다운로드 엔진 지원 완료를 뜻하지 않는다.

배포는 기존 Studio 앱/일반 브라우저 서비스의 소스 업데이트 채널을 사용한다. 신규 포트·볼륨·계정·ACL·원본 변경은 없다. 앱이 먼저 갱신되고 서비스가 아직 이전 버전이면 등록 버튼은 업데이트 대기로 비활성화된다. NAS 적용 및 실제 로그인 성공은 별도 확인 대상이다.
